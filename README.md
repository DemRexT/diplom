# Суть — учебный помощник

Прототип бакалаврского диплома на Python 3.12 / FastAPI. Загруженный учебный текст преобразуется через API нейросети в конспект, ключевые мысли, карточки и тест с обратной связью. Интерфейс на HTML/CSS/JavaScript.

## Запуск

```bash
cd /workspace/diplom
python -m venv .venv
.venv/bin/pip install -r requirements.txt
export YANDEX_API_KEY='ваш ключ' # задавайте безопасно, не сохраняйте в Git
export YANDEX_FOLDER_ID='идентификатор каталога'
export YANDEX_MODEL=yandexgpt/latest
.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Используется нативный Foundation Models API YandexGPT. Для сервисного аккаунта нужна роль `ai.languageModels.user` в каталоге Yandex Cloud, включённый биллинг и API-ключ с разрешением на вызов моделей. Ключ используется только сервером. Без ключа и ID каталога сайт открывается, обработка сообщает о недоступности. `.env.example` описывает переменные; автоматического чтения `.env` нет.

На Windows создайте окружение командой `py -3.12 -m venv .venv`, используйте `.venv\Scripts\python -m pip install -r requirements.txt` и `.venv\Scripts\python -m uvicorn app.main:app --reload`. Переменные в PowerShell задаются через `$env:YANDEX_API_KEY` и `$env:YANDEX_FOLDER_ID`.

Проверки: `.venv/bin/python -m pytest -q`. API-документация: `/docs`, состояние: `/health`.

## Ограничения прототипа

PDF с текстовым слоем или сканами, DOCX (абзацы и таблицы), TXT UTF-8; до 10 МБ и 200 страниц PDF; фиксированного ограничения в 45 000 символов больше нет. Страницы без достаточного текста распознаются локальным Tesseract OCR (до 50 страниц для OCR за загрузку). Исходные документы не сохраняются. Конспекты, карточки, вопросы, пользователи, просмотры и попытки тестирования сохраняются в базе данных. Текст передаётся внешнему провайдеру после отправки формы. Ответ нейросети проверяется по структуре, но достоверность требует сравнения с источником. Студент получает правильные ответы и объяснения только после отправки полного теста. Повторные попытки разрешены; это учебная самопроверка, не защищённый экзамен.

Перед публичным размещением необходимы HTTPS с `COOKIE_SECURE=1`, ограничение частоты/параллелизма запросов и затрат API, ограничение тела запроса на reverse proxy, изоляция парсеров документов и политика обработки данных. Сейчас это локальный прототип без этих мер.

## Развитие диплома

Перевод студентов между группами, восстановление паролей, ссылки на страницы источника, оценка качества конспектов и вопросов на наборе методичек, сравнение моделей, повторение карточек с учётом ошибок. Основной исследовательский вопрос: насколько автоматически созданные конспекты и задания помогают усвоить материал без потери ключевых фактов.


## Пользователи, роли и учебные группы

Первого администратора создайте из папки проекта локальной командой (общего пароля по умолчанию нет):

```bash
.venv/bin/python -m app.manage admin --role admin --name "Администратор"
```

На Windows:

```powershell
.\.venv\Scripts\python.exe -m app.manage admin --role admin --name "Администратор"
```

Команда запрашивает пароль дважды без отображения символов (10–128 символов). Сервер и команда должны использовать одну базу данных. Создание администратора требует доступа к серверу, через публичную регистрацию получить эту роль нельзя.

1. Администратор входит с логином `admin`, создаёт группы и аккаунты преподавателей в кабинете, назначает преподавателей в группы или убирает назначения. У преподавателя нет возможности менять эти назначения, в том числе через прямые API-запросы.
2. Между преподавателями и группами связь «многие ко многим», программного ограничения на число назначений нет. Один преподаватель может иметь много групп, одну группу могут вести несколько преподавателей.
3. Преподаватель передаёт студентам код регистрации нужной группы. Студент регистрируется по этому коду и относится к одной группе. Код даёт доступ к материалам — передавайте его только участникам группы.
4. При загрузке преподаватель выбирает одну из назначенных ему групп. Материал сохраняется как черновик; после проверки содержания и вопросов преподаватель публикует его для выбранной группы.
5. В библиотеке и на странице материала студент видит имя преподавателя и группу. Преподаватели управляют только собственными материалами, даже если несколько преподавателей назначены в одну группу.
6. Если администратор убрал преподавателя из группы, доступ к загрузке и управлению его материалами в этой группе отзывается сразу. Уже опубликованные материалы остаются доступными студентам; повторное назначение возвращает преподавателю возможность управления. Удаление назначения не удаляет материалы или результаты.
7. Статистика собственного материала содержит всех зарегистрированных студентов выбранной группы: первое и последнее открытие, число открытий, попыток и последний балл с версией теста. Открытие не подтверждает прочтение. Время хранится в UTC, интерфейс показывает время браузера.

При необходимости преподавателя без групп можно создать локально: `.venv/bin/python -m app.manage teacher --name "Иван Иванов"`. После этого администратор назначает ему группы через кабинет. Старый параметр `--group` больше не используется.

### Редактирование теста

На странице своего материала преподаватель открывает вкладку «Проверить себя»: может изменить текст вопроса, четыре варианта, правильный вариант и объяснение, добавить или удалить вопросы. После нажатия «Сохранить тест» изменения сохраняются, версия теста увеличивается и материал снимается с публикации до повторной проверки. В черновике разрешено удалить все вопросы, но для публикации нужен хотя бы один. Максимум 50 вопросов на материал.

Результаты прежних попыток не удаляются и не пересчитываются по новым ответам. В статистике указан номер версии; ответы из давно открытой вкладки не принимаются, если тест уже изменился. Одновременные изменения теста в разных вкладках защищены проверкой версии.

Пароли хешируются scrypt с индивидуальной солью. Сессии живут 24 часа, хранятся на сервере по SHA-256 от случайного токена; браузер получает HttpOnly/SameSite=Strict cookie. Выход отзывает текущую сессию. Для изменяющих API-запросов обязателен заголовок `X-Study-Request: 1`; интерфейс добавляет его автоматически. Не включайте произвольный CORS. При размещении через HTTPS задайте `COOKIE_SECURE=1`.

## База данных

По умолчанию SQLAlchemy использует SQLite в `var/study.db` (исключена из Git). Схема создаётся и обновляется через Alembic при старте. Данные переживают перезапуск; сохраните `var/` на постоянном диске и делайте резервные копии. Не включайте базу с реальными пользователями в общий снимок облачной среды.

Для PostgreSQL задайте `DATABASE_URL` в окружении сервера и административной команды, например `postgresql+psycopg://USER:PASSWORD@HOST:5432/study`. Пароль не сохраняйте в репозитории. База должна существовать заранее. PostgreSQL поддержан драйвером, но в текущей проверке использовалась SQLite; перенос существующих данных из SQLite автоматически не выполняется. Миграции находятся в `migrations/`; последующие изменения схемы нужно оформлять отдельными ревизиями Alembic.

Проверки используют отдельную базу в памяти. Полный сценарий регистрации, публикации, запрета чужих материалов, учёта просмотров и серверной проверки теста работает с имитацией YandexGPT, не расходуя API-баланс.

## Ссылки на материалы

Каждый сохранённый материал открывается по отдельному адресу `/materials/ID`, например `/materials/12`. После обработки методички сайт автоматически переходит на страницу её черновика. Библиотека содержит обычные ссылки: их можно открывать в новой вкладке. На странице есть поле для копирования адреса и ссылка возврата в библиотеку. Перезагрузка и повторное открытие ссылки не вызывают нейросеть заново.

Если пользователь не вошёл, на странице ссылки показывается вход; после входа открывается тот же материал. Доступ остаётся ограниченным: преподаватель видит свои материалы, студент — опубликованные материалы своей группы. HTML-страница представляет только оболочку интерфейса, содержимое выдаётся защищённым API. Для доступа с другого компьютера в ссылке должен использоваться доступный адрес сервера, а не localhost.

## Обновление существующего проекта

Остановите сервер и из корня проекта выполните:

```powershell
git pull origin main
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Запустите сервер привычной конфигурацией Uvicorn. При первом обновлении старой SQLite-базы автоматически сохраняется копия `var/study.db.before-groups-migration.bak`, затем существующая связь преподавателя с группой переносится в таблицу назначений. Студенты, пароли, сессии, материалы и результаты сохраняются. Повторный запуск не восстанавливает назначения, удалённые администратором. Базу и резервную копию не добавляйте в Git. Для PostgreSQL перед обновлением сделайте резервную копию средствами PostgreSQL.

После обновления создайте администратора командой выше. Существующие преподаватели продолжают пользоваться прежними аккаунтами.

## PDF-сканы и OCR

Для PDF, из которого нельзя скопировать текст, добавлено локальное распознавание. Страницы с текстовым слоем читаются напрямую; страницы с менее чем 40 символами текста и содержимым дополнительно распознаются. Поддерживаются смешанные документы. Распознанный текст передаётся в YandexGPT обычным способом. Качество зависит от чёткости, ориентации и вёрстки скана; таблицы и формулы могут распознаваться неточно.

На Windows:

1. Установите Tesseract OCR по инструкции из [официальной документации](https://tesseract-ocr.github.io/tessdoc/Installation.html) (раздел Windows; там указаны сборки для Windows). Программа ищет `tesseract` в PATH и в `C:\Program Files\Tesseract-OCR\tesseract.exe`.
2. В терминале PyCharm из корня проекта выполните:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m app.setup_ocr
```

Вторая команда скачивает официальные языковые модели rus/eng из фиксированной ревизии `tesseract-ocr/tessdata_fast` в игнорируемый каталог `var/tessdata` и проверяет SHA-256. Она не устанавливает сам движок Tesseract и не заменяет уже существующие отличающиеся модели. Библиотека PDFium для преобразования страниц в изображения устанавливается через pip; Poppler и Ghostscript не нужны.

3. Если Tesseract установлен в другой каталог, добавьте в Environment variables конфигурации Uvicorn:

```text
TESSERACT_CMD=C:\путь\к\Tesseract-OCR\tesseract.exe
```

4. Полностью перезапустите сервер и загрузите PDF ещё раз.

На Ubuntu/Debian движок ставится командой `sudo apt-get install tesseract-ocr`; затем также выполните `python -m app.setup_ocr` из виртуального окружения. В текущей облачной среде движок уже установлен.

Дополнительные переменные: `OCR_LANG` (по умолчанию `rus+eng`), `OCR_TESSDATA_DIR` (необязательный путь к языковым моделям). Без переопределения программа выбирает `var/tessdata`, если он существует, иначе использует языки установленного Tesseract.

Лимиты: до 50 распознаваемых страниц в одном PDF, до 300 секунд суммарно на OCR и 30 секунд на одну страницу. Сохраняются общий размер файла 10 МБ и максимум 200 страниц PDF. Длинный извлечённый текст автоматически обрабатывается по частям, без отказа на 45 000 символов. Рендеринг ограничен 12 млн пикселей и 10 000 пикселей по одной стороне. Временные изображения удаляются после обработки, OCR работает в потоке вне основного цикла сервера. Перед публичным размещением всё равно нужна изоляция парсеров и ограничение параллельных загрузок.

## Обработка больших методичек

Теперь цель генерации — понятный развёрнутый учебный конспект, а не короткая выжимка. Он должен объяснять понятия и взаимосвязи, сохранять содержательные темы, классификации, алгоритмы, условия, формулы и важные примеры из методички. Удаляются повторы и не относящиеся к теме вводные. В промпте задан ориентир 60–80% объёма насыщенного учебного текста, но это не обязательная длина: модель не должна придумывать сведения ради объёма.

Документ до 12 000 символов обычно обрабатывается одним запросом; при ошибке формата возможна одна дополнительная попытка исправления. Более длинный текст делится на части не более 12 000 символов, преимущественно по границам абзацев или слов. По каждой части модель отдельно пишет подробный конспект. Все разделы сохраняются последовательно в поле `summary`, без повторного сокращения общим запросом. Ограничение итогового конспекта в 10 000 символов убрано; размер конспекта растёт с размером методички. Интерфейс отображает заголовки и абзацы, старые материалы остаются совместимыми.

Для названия, главных мыслей, карточек и итогового теста выполняется отдельная общая сборка. Только для этой сборки текст длиннее 30 000 символов сокращается в служебные заметки по фрагментам не более 18 000 символов. Эти заметки при необходимости объединяются и сокращаются повторно, но подробный конспект разделов они не заменяют. Число карточек и вопросов остаётся прежним; главные мысли показываются отдельно для повторения.

Все исходные фрагменты последовательно участвуют в обработке, без обрезания конца документа. Модель всё равно может упустить детали или ошибиться, особенно после OCR; нужно сравнивать результат с методичкой перед публикацией. Реальная полнота и понятность на пользовательских методичках пока не оценивались. Уже сохранённые материалы автоматически не переписываются: для нового подробного конспекта нужно повторно загрузить исходную методичку.

Порог 45 000 символов удалён. Размеры фрагментов — внутренний бюджет отдельных запросов, а не ограничение длины всей методички и не точный токенизатор YandexGPT. Лимиты контекста зависят от выбранной модели. Сохраняются ограничения файла 10 МБ, 200 страниц PDF, 50 страниц OCR, 300 секунд на OCR и 90 секунд на отдельный запрос YandexGPT. Длинная методичка требует больше запросов, времени и оплаты; обработка идёт в рамках одного HTTP-запроса загрузки, поэтому при размещении за прокси нужно настроить достаточный тайм-аут.

При ошибке подготовки самого конспекта или обязательных карточек/теста материал не сохраняется. Ошибки необязательного интерактива не мешают сохранению готового материала. Повторная загрузка начинает обработку заново и может повторно тарифицироваться. При сетевых ошибках, ошибках HTTP или ограничениях провайдера автоматических повторов нет; для невалидного итогового JSON разрешён один отдельный запрос исправления структуры. Тесты проверяют разбиение без потерь, сохранение всех подробных разделов без замены коротким итогом, многоступенчатое сокращение только для общей сборки, сборку итогового материала и ошибки API с имитацией ответов YandexGPT.

## Ошибки нейросети в консоли PyCharm

При запуске Uvicorn сообщения `[YandexGPT]` автоматически видны во вкладке Run/Debug (или в терминале, если сервер запущен там). Для каждого вызова выводятся этап, модель, количество входных символов и лимит токенов ответа. При успешном ответе — HTTP-код, ID запроса и размер результата без его содержимого.

При ошибке API выводятся исходный HTTP-код, диагностические поля `code`/`grpcCode`/`httpCode`/`message` и ID запроса, если он есть в заголовках. Длинные сообщения сокращаются до 2000 символов. Ключ маскируется; полные запросы, заголовки авторизации, ответы модели и дополнительные поля `details` не записываются. Не-JSON тело ошибки не выводится.

Для тайм-аута, ошибки соединения, обрезанного ответа и блокировки фильтром выводится отдельное объяснение. Если нейросеть вернула невалидный JSON, в консоли будут строка и столбец ошибки; если JSON не соответствует схеме — поле и причина, например `quiz → 0 → options: too_short`. Входные значения полей при проверке схемы в лог не включаются. На сайте остаются понятные сообщения без технических подробностей. Дополнительные настройки логирования не нужны; если меняли уровень Uvicorn, `--log-level info` включает и прогресс, ошибки видны и при `--log-level error`.

## Автоматическое исправление структуры результата

Первый итоговый запрос содержит JSON Schema с обязательными полями и ограничениями. Если ответ не является валидным JSON либо не проходит проверку структуры (например, нет `title`, `key_points`, `cards`, `quiz`, неверное число вариантов или индекс ответа), сервер отправляет **ровно один** дополнительный запрос. В нём передаются исходный подготовленный материал, список ошибок без значений полей и, если они достаточно компактны, предыдущие поля карточек/теста. Ответ снова проходит ту же проверку схемы.

Готовые подробные разделы конспекта остаются в памяти текущей обработки и не генерируются заново. Если у короткого материала уже есть непустой строковый `summary`, он также сохраняется при исправлении остальных полей. Корректный ответ без ошибок дополнительных запросов не вызывает. Исправление тарифицируется как обычный запрос YandexGPT.

В консоли видны сообщения `Исправление структуры: попытка 1/1`, затем успех или отказ после второй проверки. Если исправление не удалось либо провайдер вернул ошибку, частичный материал не записывается в базу. Это сохранение в памяти одного запроса, а не долговременный кэш: после завершившейся ошибкой загрузки или перезапуска сервера повторная загрузка снова начнёт весь процесс. Сетевые ошибки, тайм-ауты, фильтр содержимого и обрезанные ответы не вызывают автоматических повторов.

## Интерактив с карточками

Раздел «Карточки» теперь открывает игру «Соедини пары»: термины и объяснения перемешиваются независимо, пользователь выбирает по одному элементу каждой колонки. Совпавшие пары отмечаются и блокируются, неверная попытка увеличивает счётчик ошибок и позволяет попробовать снова. Есть шкала прогресса, итог раунда и перезапуск с новым порядком. Элемент можно выбирать мышью или через Tab и Enter/пробел, начинать с любой колонки и отменять выбор повторным нажатием.

Режим «Повторить карточки» показывает по одной карточке с переключением между термином и объяснением, навигацией и перемешиванием. Переключение режимов сохраняет состояние текущего раунда, пока открыта страница. Игра работает с карточками уже существующих материалов и не вызывает нейросеть. Дублирующиеся термины и одинаковые объяснения объединяются для игры, чтобы не требовать угадывать между визуально одинаковыми парами; в режиме повторения остаются все исходные карточки.

Это тренировка для самопроверки: результаты игры хранятся только в памяти страницы и не попадают в преподавательскую статистику тестов. Перезагрузка страницы начинает новый раунд.

## Формулы, схемы и оформление конспекта

Конспект отображает математические формулы через KaTeX. Поддерживаются старые разделители `$...$`, `$$...$$` и новые `\(...\)`, `\[...\]`; индексы, дроби, множества и другие поддерживаемые конструкции LaTeX выводятся математическим набором. Это работает также в карточках, игре на пары, вопросах и объяснениях ответов. В редакторе преподавателя исходная разметка остаётся в полях ввода, чтобы её можно было менять. Невалидная формула не ломает остальную страницу; корректность распознанных символов после OCR по-прежнему нужно проверять.

Промпт предлагает модели добавлять небольшие Mermaid-схемы там, где источник содержит подходящие связи, классификации или процессы. Они сохраняются в тексте конспекта в блоках `mermaid` и отображаются рядом с объяснением. Поддерживаются flowchart/graph, mindmap, sequenceDiagram и pie (числа должны браться из источника). Схемы дополняют подробный текст; их наличие зависит от содержания и ответа модели. Дополнительно отображаются тематические заголовки, жирные понятия, списки и выделенные блоки `> Важно:` / `> Пример:`.

Библиотеки и математические шрифты находятся в `app/static/vendor`: дополнительная установка на ПК, Node.js и CDN не нужны. Версии, происхождение и лицензии приведены в README этого каталога. Для нового оформления и схем обновите проект и перезагрузите браузер через Ctrl+F5. Уже сохранённые корректные формулы будут отображаться сразу; новые схемы автоматически не добавляются в старые конспекты — для этого повторно загрузите исходную методичку.

Содержимое нейросети не вставляется как произвольный HTML. KaTeX работает с `trust: false`, Mermaid — с `securityLevel: strict` и отключёнными HTML-подписями; результирующий SVG дополнительно очищается DOMPurify. В схемах запрещены пользовательские настройки, HTML, ссылки, изображения и обработчики событий. Размер описания схемы ограничен 12 000 символов и 80 связями. Некорректная схема заменяется сообщением, остальная часть конспекта доступна. Схемы и формулы обрабатываются локально в браузере, дополнительный вызов нейросети для их отображения не требуется.

Конспект поддерживает Markdown: заголовки `#`–`######`, жирный текст `**...**`, курсив, вложенные списки, цитаты и таблицы. Таблицы выводятся с заголовками, границами и горизонтальной прокруткой на узких экранах. Формулы обрабатываются отдельно от Markdown, поэтому индексы, обратные слеши и символ `|` внутри формулы не повреждают разметку. Для явно оформленных строк таблицы с внешними `|` допускается пропущенная строка разделителя заголовка. Оформление применяется при просмотре, без изменения содержимого сохранённых материалов. После обновления перезапустите сервер и нажмите Ctrl+F5; повторная генерация для исправления отображения не требуется.


### Примеры задач и интерактив в теории

Для новых загрузок конспект ориентирован на 60–80% содержательной части источника: сохраняются все основные темы и хотя бы один подробный пример каждого основного типа задач (условие, метод, подстановка, промежуточные шаги и ответ). Повторные однотипные примеры группируются. Это инструкция модели, а не гарантированная доля текста: плотную главу можно сохранить почти целиком. Пропуски и точность решения преподавателю следует проверить перед публикацией.

Интерактив создаётся отдельными запросами по всем фрагментам **оригинального текста** до 8 000 символов, а не по сжатым общим заметкам. Промпт требует охватить основные формулы и каждую содержательную тему: ориентир 3–6 активностей на фрагмент. Ограничение в три примера на весь материал убрано; в одном ответе допускается до восьми экспериментов и восьми мини-миссий, результаты всех фрагментов объединяются. Фактическое количество зависит от содержания и ответа модели. Пустые служебные фрагменты могут не получить активностей. Генерация требует больше запросов и времени, чем раньше. Каждая активность проверяется отдельно: некорректные пропускаются без повторных запросов, рабочие сохраняются. Некорректный JSON пропускает только текущий фрагмент. При сетевой/HTTP-ошибке этап интерактива прекращается, уже готовый конспект, тест и корректные активности сохраняются.

В `labs` модель задаёт численные учебные примеры по формулам источника: ползунки и поля ввода, графики, полосы сравнения, двумерные векторы и матрицы 2×2 или 3×3 с подсветкой компонент. Для общей формулы разрешён явно обозначенный малый численный случай. Студент может выбирать параметр оси X и результат по оси Y, менять точку нажатием на график или клавишами ←/→, включать анимацию, сравнивать начальные/текущие значения, раскрывать расчёт и сбрасывать параметры. В режиме «Предскажи результат» параметры перемешиваются, результат и график скрываются до проверки или раскрытия ответа. Правильный прогноз отмечает эксперимент пройденным.

В `challenges` возвращаются задания по теории без вычислимых зависимостей: выбор действия/поиск ошибки и восстановление порядка шагов. Шаги перемешиваются, их можно двигать кнопками ↑/↓; после проверки показывается объяснение. Активности размещаются рядом с соответствующим заголовком; если соответствие не найдено, попадают в блок практики в конце. Наверху теории есть маршрут к активностям и счётчик пройденных миссий. Прогресс хранится только на открытой странице, без оценок в преподавательской статистике.

Все действия и вычисления выполняются локально, без новых API-запросов. Модель задаёт выражения из ограниченного набора операций; Python проверяет структуру/начальные значения, браузер вычисляет собственным парсером без `eval`. Математическая корректность и применимость требуют проверки преподавателем. Деление на ноль и выход из области определения показывают сообщение. График строится по 81 точке и не является доказательством непрерывности. Одновременно работает одна анимация; при скрытии вкладки или удалении страницы материала она останавливается. Дополнительные численные примеры помечены как примеры ИИ и не заменяют разобранные задачи методички.

Отображение формул исправляет известную ошибку группировки штриха с индексами (`\varphi'_{…}^{…}`), сохраняя исходный текст в базе. Другие невалидные формулы показываются с сообщением и кнопкой раскрытия исходной записи вместо длинной красной строки. Потерянные при OCR символы и отсутствующие в сохранённом тексте группировки (например `underbrace`) автоматически не восстанавливаются по догадке. Для новых ответов промпт требует сохранять такие обозначения.

Новых зависимостей и миграций базы нет. Уже готовые материалы не переписываются и не обогащаются примерами автоматически; изменённые инструкции применяются к следующим загрузкам. Для обновления отображения достаточно перезапуска сервера и Ctrl+F5.


Проверка интерфейса для разработчика (не требуется для обычного запуска): после установки Playwright и Chromium выполните `python scripts/check_study_browser.py`. Она открывает страницу с фиктивными данными без сервера и обращений к YandexGPT, проверяет формулы со штрихами/underbrace, обработку неверной формулы, таблицы, управление параметрами и графиком, мобильную ширину и отсутствие изменений материалов. Можно указать `--chromium /путь/к/chromium` и `--screenshot /путь/снимок.png`.


### Предпросмотр во время создания интерактива

Загрузка из браузера использует `POST /api/material?stream=true` и поток NDJSON. После подготовки конспекта, карточек и теста приходит событие `preview`: преподаватель уже может читать материал, открывать карточки и просматривать вопросы. Во время интерактива приходят события `progress`; некорректные эксперименты пропускаются. После сохранения черновика событие `complete` переводит на постоянную ссылку материала. Обычный `POST /api/material` сохраняет прежний JSON-ответ.

Предпросмотр до события `complete` не сохранён в базе: публикация, ссылка и редактирование теста недоступны. Ошибка обязательного этапа или сохранения показывается явно. При закрытии вкладки/выходе из аккаунта поток отменяется; частичный черновик не создаётся до завершения. При разрыве соединения на самом завершении сохранение могло уже произойти — проверьте библиотеку перед повторной загрузкой. Готовые ранее материалы не меняются.

Проверка предпросмотра в настоящем браузере: `python scripts/check_preview_browser.py` (те же необязательные Playwright/Chromium). Локальный HTTP-сервер отдаёт конспект до завершения потока; проверяются статус разделов, отключённое редактирование, корректное чтение UTF-8 и переход на сохранённый материал. Ключи API и база проекта не используются.
