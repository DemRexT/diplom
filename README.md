# Суть — учебный помощник

Прототип бакалаврского диплома на Python 3.12 / FastAPI. Пользователь вставляет методичку, сервер отправляет её нейросети по API и показывает результат в трёх вкладках: полный текст методички, интерактивный материал с инфографикой и тестом, чат с нейросетью по тексту методички. Сайт переключается между русским и английским языком, включая перевод самого материала. Интерфейс на HTML/CSS/JavaScript.

## Запуск

```bash
cd /workspace/diplom
python -m venv .venv
.venv/bin/pip install -r requirements.txt
export LLM_PROVIDER=gigachat
export GIGACHAT_CREDENTIALS='ваш ключ авторизации' # не сохраняйте в Git
export GIGACHAT_SCOPE=GIGACHAT_API_PERS
export GIGACHAT_MODEL=GigaChat
.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Для возврата к YandexGPT задайте `LLM_PROVIDER=yandex`, `YANDEX_API_KEY`, `YANDEX_FOLDER_ID` и при необходимости `YANDEX_MODEL=yandexgpt/latest`. Используется нативный Foundation Models API YandexGPT. Для сервисного аккаунта нужна роль `ai.languageModels.user` в каталоге Yandex Cloud, включённый биллинг и API-ключ с разрешением на вызов моделей. Ключ используется только сервером. Без ключа и ID каталога сайт открывается, обработка сообщает о недоступности. `.env.example` описывает переменные; автоматического чтения `.env` нет.

### Подключение GigaChat

Для переключения задайте процессу сервера:

```text
LLM_PROVIDER=gigachat
GIGACHAT_CREDENTIALS=ключ_авторизации_из_кабинета_GigaChat_API
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_MODEL=GigaChat
```

В PyCharm: Run → Edit Configurations → Environment variables. Записи разделяются точкой с запятой (или добавляются отдельными строками в редакторе). Используйте **ключ авторизации** API из кабинета GigaChat; не токен доступа от веб-чата и не Yandex API key. Не присылайте ключ в переписку и не сохраняйте в Git. Для личного аккаунта используется `GIGACHAT_API_PERS`; для бизнес-доступа задайте соответствующий scope из своего кабинета (`GIGACHAT_API_B2B` или `GIGACHAT_API_CORP`). Модель задаётся идентификатором, доступным вашему аккаунту; `GigaChat` — начальная настройка, стоимость и доступность проверяются у провайдера.

Сервер обменивает ключ на временный access token через `https://ngw.devices.sberbank.ru:9443/api/v2/oauth`, использует Bearer для `https://api.giga.chat/v1/chat/completions`, повторно использует токен внутри одной обработки и обновляет по сроку действия. При явном HTTP 401 токен обновляется и запрос повторяется ровно один раз. Тайм-ауты, ограничения частоты и прочие HTTP-ошибки автоматически не повторяются. JSON запрашивается промптом со схемой, не через неподдерживаемое предположение об OpenAI `response_format`.

Проверка TLS не отключается. Если появляется ошибка проверки сертификата, установите доверенные сертификаты согласно официальной инструкции GigaChat и при необходимости укажите PEM-файл в `GIGACHAT_CA_BUNDLE`. Приложение добавляет его к системным доверенным сертификатам; неверный файл приводит к понятной ошибке настройки. Альтернатива — стандартный `SSL_CERT_FILE` для HTTPX. Не используйте `verify=False`. Справка провайдера: [авторизация](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/post-token), [запрос к модели](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/post-chat).

После изменения переменных перезапустите сервер. `/health` показывает выбранного провайдера и наличие обязательных переменных, но не проверяет баланс и действительность ключа. Без `LLM_PROVIDER` остаётся YandexGPT для совместимости; для возврата задайте `LLM_PROVIDER=yandex`. Старые материалы не переписываются. Проверка JSON, вопросы по методичке и роли работают с обоими провайдерами. Новых Python-зависимостей не требуется. Платный запрос с реальным GigaChat-ключом не выполнялся: автоматические проверки используют имитацию OAuth и ответов API.

На Windows создайте окружение командой `py -3.12 -m venv .venv`, используйте `.venv\Scripts\python -m pip install -r requirements.txt` и `.venv\Scripts\python -m uvicorn app.main:app --reload`. Переменные в PowerShell задаются через `$env:LLM_PROVIDER="gigachat"`, `$env:GIGACHAT_CREDENTIALS="ваш ключ"`, `$env:GIGACHAT_SCOPE="GIGACHAT_API_PERS"`, `$env:GIGACHAT_MODEL="GigaChat"`.

Проверки: `.venv/bin/python -m pytest -q`. API-документация: `/docs`, состояние: `/health`.

## Ограничения прототипа

PDF с текстовым слоем или сканами, DOCX (абзацы и таблицы), TXT UTF-8; до 10 МБ и 200 страниц PDF; фиксированного ограничения в 45 000 символов больше нет. Страницы без достаточного текста распознаются локальным Tesseract OCR (до 50 страниц для OCR за загрузку). Сами файлы не сохраняются, но извлечённый из них текст хранится в базе вместе с сутью, тестом, вопросами и ответами и попытками тестирования. Текст передаётся внешнему провайдеру после отправки формы. Ответ нейросети проверяется по структуре, но достоверность требует сравнения с источником. Правильные ответы и объяснения показываются только после отправки полного теста. Повторные попытки разрешены; это учебная самопроверка, не защищённый экзамен.

Вход и учётные записи отсутствуют: любой, кто может открыть адрес сервера, видит все материалы, загружает новые (тратя баланс API) и редактирует тесты. Поэтому запускайте сервер только локально (`127.0.0.1`) или в доверенной сети. Перед публичным размещением необходимы авторизация, HTTPS, ограничение частоты/параллелизма запросов и затрат API, ограничение тела запроса на reverse proxy, изоляция парсеров документов и политика обработки данных. Сейчас это локальный прототип без этих мер.

Ссылки на страницы источника, оценка качества сути и ответов на вопросы на наборе методичек, сравнение моделей. Основной исследовательский вопрос: насколько автоматически выделенная суть и ответы по тексту помогают усвоить материал без потери ключевых фактов.


## Без авторизации

Приложение работает без входа, регистрации, ролей и групп: сразу открывается форма загрузки методички. Библиотеки (списка материалов) нет: после обработки открывается страница материала, вернуться к нему можно по её ссылке. Все действия выполняет один встроенный пользователь `local` (группа «Мои материалы»), он создаётся автоматически при первом запросе (`app/local.py`). Так материалы, попытки и вопросы по-прежнему ссылаются на пользователя и группу, и схема базы не меняется.

Если в базе остались аккаунты, группы и сессии из прежней версии, они не удаляются, но больше не используются. В библиотеке показываются все материалы базы, включая загруженные раньше другими преподавателями. Флаг публикации и учёт просмотров в интерфейсе и API больше не используются.

Для изменяющих API-запросов по-прежнему обязателен заголовок `X-Study-Request: 1` (интерфейс добавляет его сам): это защищает от отправки форм с чужих сайтов. Не включайте произвольный CORS.

### Редактирование теста

Тест «Проверь себя» находится в конце вкладки «Интерактивный материал». Нажмите «Редактировать тест»: можно изменить текст вопроса, четыре варианта, правильный вариант и объяснение, добавить или удалить вопросы. После нажатия «Сохранить тест» изменения сохраняются и версия теста увеличивается. Разрешено удалить все вопросы. Максимум 50 вопросов на материал. Тест редактируется на языке, на котором материал был создан; перевод теста обновляется при следующем переключении языка.

Результаты прежних попыток не удаляются и не пересчитываются по новым ответам, у каждой попытки сохраняется номер версии теста. Ответы из давно открытой вкладки не принимаются, если тест уже изменился. Одновременные изменения теста в разных вкладках защищены проверкой версии.

## База данных

По умолчанию SQLAlchemy использует SQLite в `var/study.db` (исключена из Git). Схема создаётся и обновляется через Alembic при старте. Данные переживают перезапуск; сохраните `var/` на постоянном диске и делайте резервные копии. Не включайте базу с реальными данными в общий снимок облачной среды.

Для PostgreSQL задайте `DATABASE_URL` в окружении сервера, например `postgresql+psycopg://USER:PASSWORD@HOST:5432/study`. Пароль не сохраняйте в репозитории. База должна существовать заранее. PostgreSQL поддержан драйвером, но в текущей проверке использовалась SQLite; перенос существующих данных из SQLite автоматически не выполняется. Миграции находятся в `migrations/`; последующие изменения схемы нужно оформлять отдельными ревизиями Alembic.

Проверки используют отдельную базу в памяти. Полный сценарий загрузки, теста, редактирования теста и вопросов работает с имитацией YandexGPT, не расходуя API-баланс.

## Ссылки на материалы

Каждый сохранённый материал открывается по отдельному адресу `/materials/ID`, например `/materials/12`. После обработки методички сайт автоматически переходит на её страницу. На странице есть поле для копирования адреса и ссылка «Загрузить другую методичку». Перезагрузка и повторное открытие ссылки не вызывают нейросеть заново.

Ссылку может открыть любой, кто имеет доступ к серверу. Для доступа с другого компьютера в ссылке должен использоваться доступный адрес сервера, а не localhost.

## Как это работает

1. Пользователь выбирает методичку (PDF, DOCX или TXT) и нажимает «Разобрать материал».
2. Сервер извлекает текст и по API отправляет его нейросети (GigaChat или YandexGPT); длинные тексты обрабатываются по частям. Запросы идут в три этапа:
   1. конспект и тест (JSON);
   2. инфографика — отдельный JSON-запрос (`app/enrich.py`);
   3. проверка текста методички (`app/guide.py`), фрагментами по ~8 000 символов — см. «Проверка текста».
3. Когда ответ получен, открывается страница материала с двумя вкладками:
   1. **Методичка** — текст точно такой, как в файле, меняется только оформление (`app/layout.py`). Программа склеивает строки, разорванные переносами PDF, распознаёт заголовки, списки, таблицы и определения («Термин — …» выделяется жирным). Нейросеть текст не переписывает: она только указывает заголовки и формулы. Формула заменяется записью LaTeX, только если в ней ровно те же буквы и цифры, что в оригинале (например, `x2 + y2 = r2` → \(x^2+y^2=r^2\)); остальное остаётся как есть. Программный код (MATLAB, Python и т. п.) распознаётся и показывается моноширинным блоком с сохранёнными строками и отступами; фрагменты кода никогда не превращаются в формулы. PDF читается двумя режимами pypdf сразу (`app/pdftext.py`): режим `layout` правильно передаёт переносы строк, отступы кода и столбцы таблиц, но в PDF из Word вставляет пробелы внутрь слов при выравнивании по ширине («формализ   овывать»); обычный режим держит слова целыми, но склеивает строки. Символы в обоих одинаковы, поэтому они сопоставляются: переносы и отступы берутся из `layout`, а пробел внутри строки остаётся, только если он есть и в обычном режиме. Кнопка «Показать текст как в файле» открывает исходное извлечение. Материалы, загруженные раньше, оформляются так же автоматически, без запросов к нейросети (если автор не правил текст вручную). Но ошибки старого извлечения PDF (склеенные слова, перепутанный порядок блоков) так не исправить — загрузите такую методичку заново.
   2. **Интерактивный материал** — главное из методички. Сверху содержание со ссылками на темы, каждую тему можно свернуть. Внутри тем — инфографика и кнопка «Спросить нейросеть об этой теме». Ниже — тест «Проверь себя» и **чат с нейросетью**: ответы строятся только по тексту методички, история сохраняется.

Инфографика и подсказки оформления — дополнительные этапы: если на них нейросеть ошибётся или будет недоступна, материал всё равно сохранится (текст оформляется без подсказок, инфографики нет), а причина появится в консоли сервера.

### Проверка текста первой вкладки

Текст, извлечённый из PDF, часто испорчен: слова склеены («системыв»), разорваны, строки кода слиты, таблицы вытянуты в строку, формулы набраны обычным текстом. Поэтому каждый фрагмент методички проверяется: нейросеть указывает ошибки, а сервер применяет только безопасные исправления.

| Что ищется | Когда исправление принимается |
| --- | --- |
| Склеенные и разорванные слова, слитые строки кода | Меняются только пробелы и переносы строк; буквы, цифры и знаки — те же и в том же порядке |
| Таблицы, вытянутые в строку | Ячейки таблицы подряд дают ровно исходный текст фрагмента |
| Формулы | Запись LaTeX содержит ровно те же буквы и цифры, что оригинал |
| Заголовки | Строка заголовка дословно есть в тексте |

Лишние пробелы в тексте убираются программно (в коде отступы сохраняются). Таблицы, где столбцы в PDF разделены пробелами, распознаются и без нейросети. Все формулы набираются KaTeX и показываются в рамке: отдельной строкой — в блоке, внутри текста — в небольшой рамке.

Над текстом методички показывается отчёт: «Текст проверен: все N слов из файла на месте, исправлено …», список исправлений и места, которые стоит посмотреть вручную (склейки, которые нельзя исправить без риска изменить текст; их можно поправить в редакторе). У материалов, загруженных раньше, автор запускает проверку кнопкой «Проверить текст» (`POST /api/materials/{id}/check`, только с ключом редактирования); ручные правки автора сохраняются, к ним применяются только исправления пробелов.

#### Оформление без нейросети работает на любых методичках

Основа оформления первой вкладки — правила `app/layout.py`, а не подгонка под один файл. Они рассчитаны на методички разных видов:

| Что в методичке | Как распознаётся |
| --- | --- |
| Заголовки | Нумерованные («2.», «3.1.»), «Глава/Раздел/Лекция/Lab N», «Шаг/Вариант/Задание N», строки капсом, а также короткие строки без номера между абзацами («Периодизация»). Заголовки DOCX — по стилю |
| Списки | Маркеры •, –, *, символы шрифтов Symbol/Wingdings из PDF, «1.», «а)»; нумерация Word из DOCX восстанавливается; перенесённый на следующую строку пункт остаётся в своём пункте; «4. Контрольные вопросы» перед вопросами 5, 6, 7 — заголовок, а не пункт |
| Таблицы | Таблицы DOCX; в PDF и TXT — столбцы, выровненные пробелами (допускается сдвиг на 1–3 символа у чисел, продолжение ячейки на следующей строке, склеенная строка внутри таблицы) |
| Код | MATLAB, Python, C/C++, Java, SQL: ключевые слова, `#include`, аннотации `@Override`, присваивания, вызовы, скобки; строки внутри оператора и перенесённые по ширине страницы остаются в блоке кода; строки таблиц со словами `public`/`int` кодом не считаются |
| Нумерация разделов | «8. Список источников», после которого Word продолжил нумерацию (9, 10, 11), — заголовок раздела: строка продолжает номера разделов документа или начинается со слова раздела («Список», «Вопросы», «Задания», «Приложение», References…), а пункты под ней остаются списком со своими номерами. Номер без пробела («10.Леоненков») тоже понимается |
| Правила и перечисления в строку | «ПРАВИЛО 1: … ПРАВИЛО 2: …», «Шаг 1. … Шаг 2. …» внутри абзаца — отдельные пункты с жирной меткой; в правилах выделены ЕСЛИ / И / ИЛИ / ТО (IF / THEN), пары `признак=значение` показаны как значения (`app/richtext.py`) |
| Формулы и расчёты в тексте | Запись с «=», «≤», индексами (x_n, μ_низкий), степенями (x²), штрихами (f′) становится формулой KaTeX: короткая — в строке, длинная цепочка вычислений или формула после двоеточия — отдельной строкой в рамке; формула на своей строке — тоже в рамке. Буквы и цифры формулы проверяются на совпадение с текстом; упоминания кода (`for i = 1:n`) формулами не считаются |
| Вводные слова | «Вывод из примера.», «Пример:», «Пояснение:», «Примечание:», «Важно:» — жирным; «Важно» и «Примечание» — выделенным блоком |
| Рисунки | Картинки из PDF (pypdfium2: место на странице — после текста над рисунком) и DOCX сохраняются в `var/media/`, отдаются по `GET /api/materials/{id}/images/{n}` и показываются в тексте на своём месте, над подписью «Рисунок N — …»; нажатие увеличивает. Картинка из PDF берётся снимком её видимой части (с обрезкой и поворотом, как на странице). Рисунок всегда виден целиком, по нажатию открывается на весь экран (ещё нажатие — натуральный размер, Esc — закрыть); схемы масштабируются под ширину страницы и тоже открываются на весь экран; широкие таблицы (от 5 столбцов) получают более плотные ячейки с переносом текста и помещаются по ширине без прокрутки. Мелкие значки и сканы целых страниц пропускаются. Схемы, нарисованные фигурами Word (блок-схемы, SmartArt, диаграммы), тоже становятся рисунками: в PDF находится область залитых фигур с промежутками между ними и стрелками (таблица — только тонкие линии, заливка абзаца — одна полоса во всю ширину, заливка ячеек — фигуры вплотную друг к другу; это не схемы) и сохраняется её снимок; в DOCX описание фигур (прямоугольники, ромбы, скругления, эллипсы, параллелограммы, стрелки и соединители, группы, полотна, SmartArt) рисуется модулем `app/shapes.py`. Подписи из фигур видны на рисунке, поэтому в оформленном тексте под схемой не повторяются (в извлечённом тексте они остаются). В JSON материала хранятся только имена файлов, размеры и «якорь» (текст перед рисунком), сам текст методички не меняется |
| Таблицы из подсказок нейросети | Принимаются, только если похожи на таблицу (`table_like`): ячейки-абзацы, ячейка-заголовок («Вариант 7. …»), перечисление «Признаки: а; б; в» в ячейке или почти пустые строки — отказ. Принятые подсказки (заголовки, формулы, таблицы) хранятся в материале (`layout_hints`), поэтому при улучшении правил текст переоформляется без нового запроса к нейросети |
| Формулы в PDF из LaTeX и Word | Если заметная часть символов набрана математическими шрифтами (CMMI/CMSY/CMEX, Latin Modern Math, Cambria Math…), PDF читается посимвольно (`app/mathpdf.py`): строки определяются по геометрии, формула в строке восстанавливается в LaTeX по размеру и высоте символов (индексы, степени, вложенные индексы) и показывается KaTeX; выносная формула в один уровень — тоже LaTeX, а с дробями, суммами с пределами, системами и матрицами — снимком этой части страницы (без рамки, высотой как в оригинале). Слова рядом с формулой остаются текстом |
| Формулы без названий шрифтов | Если имена шрифтов стёрты (конвертеры, «оптимизаторы» PDF), формулу узнают по самим символам: греческие буквы и математические знаки, индексы (уменьшенные и сдвинутые относительно строки), одиночные латинские буквы среди русского текста, короткие курсивные имена; цифры и знаки входят в формулу только рядом с ней, скобки — по балансу. Режим формул включается только по сильным признакам (у обычных методичек их доли процента). Фрагмент, который нельзя прочитать (символы без кодов, дробь в строке), показывается маленьким снимком прямо в строке |
| Формулы Word в DOCX | Редактор формул Word (OMML) переводится в LaTeX (`app/omml.py`): дроби, корни, индексы и степени, суммы и интегралы с пределами, скобки, функции, акценты, черта, матрицы, системы; формула в строке — `\( … \)`, отдельной строкой — `\[ … \]`. Раньше такие формулы пропадали |
| Заголовки PDF по шрифту | Короткая строка, набранная крупнее основного текста или целиком полужирным, — заголовок (подсказка для оформления, как от нейросети). Три строки подряд одного вида — это абзац (предисловие крупным шрифтом, примечание полужирным), а не заголовки; строка во всю ширину, чьё предложение продолжается ниже, — начало абзаца. Слова «Глава», «Тема», «Лекция», «Раздел» делают строку заголовком только с номером; если под «заголовком» предложение продолжается с маленькой буквы, это снова абзац |
| Номера страниц | Номер страницы отдельной строкой вверху или внизу страницы PDF в текст не попадает |
| Переносы слов | «устра-нения» склеивается, а «блок-схема», «научно-технический», «кто-то» сохраняют дефис (решение по словарю самого текста и составным словам) |

Это проверяет `tests/test_corpus.py`: восемь разных методичек (программирование на Python, SQL, численные методы с формулами, гуманитарная лекция без кода, лабораторная по C с таблицами вариантов, английская методичка по Java, учебное пособие по сетям, лабораторная по экспертным системам с правилами в строку, расчётами, рисунками и продолженной нумерацией), каждая в DOCX, TXT и PDF двух видов: обычная страница и узкая колонка с автоматическими переносами. Всего 32 варианта. Тест сверяет результат с эталоном: каждое слово цело и на месте, таблицы — таблицы с теми же ячейками, код — в блоках кода, заголовки (и нумерованные разделы) и списки распознаны, обычный текст не стал кодом или списком, правила разбиты по пунктам, расчёты стали формулами, каждый рисунок стоит над своей подписью. PDF-файлы лежат в `tests/corpus` (DOCX собирает `tests/corpus/build.py`, PDF из них делает LibreOffice), DOCX и TXT тест собирает сам. Если меняете правила оформления — запустите этот тест.

### Редактирование и ссылка для просмотра

Автор может изменить название, текст методички, текст интерактивного материала и тест: кнопки «Изменить название», «Редактировать методичку», «Редактировать текст», «Редактировать тест». Текст редактируется в Markdown с предпросмотром. Если на экране перевод, правится перевод, а оригинал не меняется; правка оригинала сбрасывает перевод изменённых частей, и он выполняется заново при следующем переключении языка. Чат отвечает по тексту методички с учётом правок.

Право редактировать даёт секретный ключ, который сервер выдаёт при загрузке; браузер автора хранит его в `localStorage`. Кнопка «Поделиться ссылкой» показывает обычную ссылку `/materials/ID` — по ней материал открывается **только для просмотра**: кнопок редактирования нет, а сервер отклоняет любые изменения без ключа (HTTP 403). Тест и чат получателю доступны. Там же есть «Ссылка для редактирования на другом устройстве» (`/materials/ID#edit=ключ`) — её не передают другим. У материалов, созданных до появления ключей, ключ создаётся при первом нажатии «Поделиться», и с этого момента править их может только этот браузер.

API: `PUT /api/materials/{id}/content` (`lang`, `title`, `formatted`, `summary`) и `PUT /api/materials/{id}/quiz` требуют заголовок `X-Edit-Key`; `POST /api/materials/{id}/share` возвращает `view_url` и ключ; поле `editable` в ответе показывает, может ли текущий браузер редактировать.

### Инфографика

Нейросеть возвращает JSON со списком элементов, каждый привязан к теме конспекта. Сервер проверяет структуру и отбрасывает неполные элементы, а интерфейс рисует их сам — без HTML от модели.

| Тип | Что показывает |
| --- | --- |
| `flow` | Блок-схема алгоритма: начало/конец, действия, условия-ромбы с подписями «да/нет» (Mermaid) |
| `formula` | Карточка формулы: формула крупно в рамке и расшифровка каждого обозначения |
| `code` | Разбор кода: листинг с номерами строк, нажатие на отмеченную строку показывает пояснение. Код принимается, только если он действительно есть в методичке (≥80% строк) |
| `facts` | Карточки «Ключевые факты» с числами и величинами из текста (значение — короткое число, не фраза) |
| `steps` | Пошаговый разбор алгоритма: шаги листаются кнопками «Назад/Далее» или выбираются |
| `terms` | Карточки терминов: нажатие открывает определение |
| `tree` | Схема-классификация (до 3 уровней), строится через Mermaid из данных |
| `timeline` | Хронология |
| `chart` | Столбчатая диаграмма по числам из текста |

Промпт запрещает выдумывать данные: нет чисел в методичке — нет фактов и диаграмм. Чтобы пособие было разнообразным, каждый тип допускается не больше двух раз (сервер отбрасывает лишние), а в первую очередь нейросеть ищет алгоритмы, формулы и код. При переводе меняются только подписи: код, LaTeX и связи блок-схемы берутся из оригинала. В материалах, загруженных раньше, нет оформленного текста и инфографики — загрузите методичку заново.

## Русский и английский язык

Кнопки RU / EN в шапке переключают язык сайта; выбор запоминается в браузере.

- Интерфейс, подсказки и сообщения об ошибках сервера переводятся сразу (тексты интерфейса — `app/static/i18n.js`, сообщения сервера — `app/i18n.py`, браузер передаёт язык заголовком `X-Lang`).
- Новая методичка обрабатывается на языке сайта в момент загрузки: на нём нейросеть пишет интерактивный материал и тест.
- При переключении на другой язык на странице материала нейросеть один раз переводит всё: оформленную методичку и интерактивный материал (по целым темам, разметка и формулы сохраняются), инфографику (числа берутся из оригинала) и тест (правильные ответы не меняются). Пока идёт перевод, показан оригинал и индикатор с таймером. Перевод сохраняется в базе вместе с материалом (JSON-поле `content`, схема таблиц не меняется), поэтому повторные переключения мгновенны и не тратят запросы. Каждая готовая часть сохраняется сразу: если перевод прервался, повтор доделывает только недостающее.
- Чат отвечает на языке сайта и ищет фрагменты в методичке на том же языке.
- Перевод большой методички — это много платных запросов и несколько минут. Перевод выполняется нейросетью и может содержать неточности.

API: `GET /api/materials/{id}?lang=en` возвращает материал на английском, если перевод готов (поле `lang` в ответе показывает фактический язык); `POST /api/materials/{id}/translation?lang=en` выполняет перевод (поток NDJSON: `heartbeat`, затем `complete` или `error`).

## Обработка больших методичек

Документ до 30 000 символов отправляется для выделения сути одним запросом. Более длинный текст сначала делится на фрагменты не более 18 000 символов (по границам абзацев или слов), по каждому модель пишет опорные заметки; при необходимости заметки объединяются и сокращаются повторно. Суть и тест строятся по этим заметкам. Все фрагменты участвуют в обработке, конец документа не обрезается. Порог 45 000 символов удалён.

Модель может упустить детали или ошибиться, особенно после OCR; сверяйте суть с вкладкой «Методичка».

При ошибке подготовки сути или теста материал не сохраняется. Повторная загрузка начинает обработку заново и может повторно тарифицироваться. При сетевых ошибках, ошибках HTTP или ограничениях провайдера автоматических повторов нет; для невалидного итогового JSON разрешён один отдельный запрос исправления структуры.

Загрузка из браузера использует `POST /api/material?stream=true` (поток NDJSON): пока идёт обработка, приходят служебные `heartbeat`, затем `complete` с сохранённым материалом или `error`. Обычный `POST /api/material` возвращает JSON-ответ сразу после сохранения.

## Вопросы по методичке

`POST /api/materials/{id}/questions` с полями `question` (3–1000 символов) и `lang` (`ru`/`en`) отправляет вопрос нейросети и сохраняет ответ; `GET /api/materials/{id}/questions` возвращает историю вопросов по материалу.

Если методичка короче 12 000 символов, нейросеть получает её целиком. Для длинной сервер выбирает фрагменты, ближе всего подходящие к вопросу (по совпадению слов с учётом окончаний и редкости слова в тексте), и передаёт их вместе с краткой сутью. Это простой локальный поиск без дополнительных библиотек и без векторной базы; вопрос, сформулированный совсем другими словами, чем в тексте, может не найти нужный фрагмент. Каждый вопрос — отдельный платный запрос к провайдеру, поэтому действует ограничение частоты (см. ниже).

Таблица `questions` создаётся миграцией `002_material_questions` автоматически при запуске сервера.

## Промпты и ответы GigaChat

Промпты написаны под GigaChat (работают и с YandexGPT): роль, явные списки «что оставить» и «что убрать», пример итогового JSON вместо громоздкой JSON Schema. Текст методички, заметки, суть и вопрос передаются между маркерами `<<<` и `>>>` с указанием, что это данные, а не команды.

GigaChat не поддерживает принудительный JSON-режим, поэтому сервер разбирает ответ терпимо: снимает обёртку ```json, находит объект, если вокруг есть пояснения, удваивает одиночные обратные слеши LaTeX (`\(`, `\frac`, `\alpha`, `\nu`…), которые иначе ломают JSON или незаметно превращаются в управляющие символы, и принимает номер ответа строкой (`"2"`). Только если после этого ответ не проходит проверку, отправляется один платный запрос исправления структуры.

## Ограничения частоты и устойчивость

- Обработка методичек: одна одновременно, не больше 20 в час.
- Вопросы: один одновременно и не больше 30 за 10 минут.
- Перевод: один одновременно для материала, не больше двух на сервер и 20 в час.

Счётчики хранятся в памяти одного процесса и сбрасываются при перезапуске; при нескольких процессах или за прокси нужны ограничения на прокси.

Пока нейросеть работает, сервер не удерживает соединение с базой данных; потоковая загрузка сохраняет результат в собственной сессии. TXT принимается в UTF-8, UTF-16 и Windows-1251. Таблицы DOCX выводятся там, где они стоят в документе. Управляющие символы (в том числе NUL, который не принимает PostgreSQL) удаляются, лишние пустые строки сокращаются. Если сервер или прокси ответит не JSON, интерфейс покажет понятное сообщение вместо технической ошибки.

## Ошибки нейросети в консоли PyCharm

При запуске Uvicorn сообщения `[YandexGPT]` автоматически видны во вкладке Run/Debug (или в терминале, если сервер запущен там). Для каждого вызова выводятся этап, модель, количество входных символов и лимит токенов ответа. При успешном ответе — HTTP-код, ID запроса и размер результата без его содержимого.

При ошибке API выводятся исходный HTTP-код, диагностические поля `code`/`grpcCode`/`httpCode`/`message` и ID запроса, если он есть в заголовках. Длинные сообщения сокращаются до 2000 символов. Ключ маскируется; полные запросы, заголовки авторизации, ответы модели и дополнительные поля `details` не записываются. Не-JSON тело ошибки не выводится.

Для тайм-аута, ошибки соединения, обрезанного ответа и блокировки фильтром выводится отдельное объяснение. Если нейросеть вернула невалидный JSON, в консоли будут строка и столбец ошибки; если JSON не соответствует схеме — поле и причина, например `quiz → 0 → options: too_short`. Входные значения полей при проверке схемы в лог не включаются. На сайте остаются понятные сообщения без технических подробностей. Дополнительные настройки логирования не нужны; если меняли уровень Uvicorn, `--log-level info` включает и прогресс, ошибки видны и при `--log-level error`.

## Автоматическое исправление структуры результата

Первый итоговый запрос содержит JSON Schema с обязательными полями и ограничениями. Если ответ не является валидным JSON либо не проходит проверку структуры (например, нет `title`, `summary`, `quiz`, неверное число вариантов или индекс ответа), сервер отправляет **ровно один** дополнительный запрос. В нём передаются исходный подготовленный материал, список ошибок без значений полей и, если они достаточно компактны, предыдущие поля названия и теста. Ответ снова проходит ту же проверку схемы.

Если в первом ответе уже есть непустой строковый `summary`, он сохраняется при исправлении остальных полей и не генерируется заново. Корректный ответ без ошибок дополнительных запросов не вызывает. Исправление тарифицируется как обычный запрос YandexGPT.

В консоли видны сообщения `Исправление структуры: попытка 1/1`, затем успех или отказ после второй проверки. Если исправление не удалось либо провайдер вернул ошибку, частичный материал не записывается в базу. Это сохранение в памяти одного запроса, а не долговременный кэш: после завершившейся ошибкой загрузки или перезапуска сервера повторная загрузка снова начнёт весь процесс. Сетевые ошибки, тайм-ауты, фильтр содержимого и обрезанные ответы не вызывают автоматических повторов.

## Формулы, схемы и оформление

Суть и ответы отображают математические формулы через KaTeX. Поддерживаются старые разделители `$...$`, `$$...$$` и новые `\(...\)`, `\[...\]`; индексы, дроби, множества и другие поддерживаемые конструкции LaTeX выводятся математическим набором. Это работает также в ответах на вопросы, вопросах теста и объяснениях ответов. В редакторе преподавателя исходная разметка остаётся в полях ввода, чтобы её можно было менять. Невалидная формула не ломает остальную страницу; корректность распознанных символов после OCR по-прежнему нужно проверять.

Mermaid-схемы сохраняются в тексте материала в блоках `mermaid` и отображаются рядом с объяснением. Поддерживаются flowchart/graph, mindmap, timeline, sequenceDiagram и pie (числа должны браться из источника). Дополнительно отображаются тематические заголовки, жирные понятия, списки и выделенные блоки `> Важно:` / `> Пример:`.

Библиотеки и математические шрифты находятся в `app/static/vendor`: дополнительная установка на ПК, Node.js и CDN не нужны. Версии, происхождение и лицензии приведены в README этого каталога. Для нового оформления и схем обновите проект и перезагрузите браузер через Ctrl+F5. Уже сохранённые корректные формулы будут отображаться сразу; новые схемы автоматически не добавляются в старые материалы — для этого повторно загрузите исходную методичку.

Содержимое нейросети не вставляется как произвольный HTML. KaTeX работает с `trust: false`, Mermaid — с `securityLevel: strict` и отключёнными HTML-подписями; результирующий SVG дополнительно очищается DOMPurify. В схемах запрещены пользовательские настройки, HTML, ссылки, изображения и обработчики событий. Размер описания схемы ограничен 12 000 символов и 80 связями. Некорректная схема заменяется сообщением, остальная часть текста доступна. Схемы и формулы обрабатываются локально в браузере, дополнительный вызов нейросети для их отображения не требуется.

Суть поддерживает Markdown: заголовки `#`–`######`, жирный текст `**...**`, курсив, вложенные списки, цитаты и таблицы. Таблицы выводятся с заголовками, границами и горизонтальной прокруткой на узких экранах. Формулы обрабатываются отдельно от Markdown, поэтому индексы, обратные слеши и символ `|` внутри формулы не повреждают разметку. Для явно оформленных строк таблицы с внешними `|` допускается пропущенная строка разделителя заголовка. Оформление применяется при просмотре, без изменения содержимого сохранённых материалов. После обновления перезапустите сервер и нажмите Ctrl+F5; повторная генерация для исправления отображения не требуется.


Проверка интерфейса для разработчика (не требуется для обычного запуска): после установки Playwright и Chromium выполните `python scripts/check_study_browser.py`. Она открывает страницу с фиктивными данными без сервера и обращений к нейросети, проверяет формулы, обработку неверной формулы, таблицы, вывод полного текста без выполнения разметки, отправку вопроса и мобильную ширину. Можно указать `--chromium /путь/к/chromium` и `--screenshot /путь/снимок.png`.
