# Суть — учебный помощник

Прототип бакалаврского диплома на Python 3.12 / FastAPI. Загруженный учебный текст преобразуется через API нейросети в конспект, ключевые мысли, карточки и тест с обратной связью. Интерфейс на HTML/CSS/JavaScript.

## Запуск

```bash
cd /workspace/diplom
python -m venv .venv
.venv/bin/pip install -r requirements.txt
export YANDEX_API_KEY='ваш ключ' # задавайте безопасно, не сохраняйте в Git
export YANDEX_FOLDER_ID='идентификатор каталога'
export YANDEX_MODEL=yandexgpt/latest
.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Используется нативный Foundation Models API YandexGPT. Для сервисного аккаунта нужна роль `ai.languageModels.user` в каталоге Yandex Cloud, включённый биллинг и API-ключ с разрешением на вызов моделей. Ключ используется только сервером. Без ключа и ID каталога сайт открывается, обработка сообщает о недоступности. `.env.example` описывает переменные; автоматического чтения `.env` нет.

На Windows создайте окружение командой `py -3.12 -m venv .venv`, используйте `.venv\Scripts\python -m pip install -r requirements.txt` и `.venv\Scripts\python -m uvicorn app.main:app --reload`. Переменные в PowerShell задаются через `$env:YANDEX_API_KEY` и `$env:YANDEX_FOLDER_ID`.

Проверки: `.venv/bin/python -m pytest -q`. API-документация: `/docs`, состояние: `/health`.

## Ограничения прототипа

PDF с текстовым слоем, DOCX (абзацы и таблицы), TXT UTF-8; до 10 МБ, 200 страниц PDF и 45 000 символов. OCR не включён. Исходные документы не сохраняются. Конспекты, карточки, вопросы, пользователи, просмотры и попытки тестирования сохраняются в базе данных. Текст передаётся внешнему провайдеру после отправки формы. Ответ нейросети проверяется по структуре, но достоверность требует сравнения с источником. Студент получает правильные ответы и объяснения только после отправки полного теста. Повторные попытки разрешены; это учебная самопроверка, не защищённый экзамен.

Перед публичным размещением необходимы HTTPS с `COOKIE_SECURE=1`, ограничение частоты/параллелизма запросов и затрат API, ограничение тела запроса на reverse proxy, изоляция парсеров документов и политика обработки данных. Сейчас это локальный прототип без этих мер.

## Развитие диплома

Несколько групп у преподавателя, управление участниками, миграции схемы через Alembic, восстановление паролей, ссылки на страницы источника, оценка качества конспектов и вопросов на наборе методичек, сравнение моделей, повторение карточек с учётом ошибок. Основной исследовательский вопрос: насколько автоматически созданные конспекты и задания помогают усвоить материал без потери ключевых фактов.


## Пользователи, роли и учебные группы

После установки зависимостей создайте преподавателя локальной административной командой:

```bash
.venv/bin/python -m app.manage teacher --name "Иван Иванов" --group "ИВТ-41"
```

На Windows: `.venv\Scripts\python -m app.manage teacher --name "Иван Иванов" --group "ИВТ-41"`.
Команда запрашивает пароль дважды без отображения символов (минимум 10 символов) и выдаёт код регистрации группы. Пароли по умолчанию отсутствуют. Сервер и команда должны использовать одну базу данных.

1. Преподаватель входит через сайт и передаёт студентам код группы, который также виден в его кабинете.
2. Студент открывает «Регистрация студента», вводит имя, логин, пароль и код. Роль преподавателя через публичную регистрацию получить нельзя.
3. Преподаватель загружает методичку. Результат сохраняется как черновик; после проверки он нажимает «Опубликовать для группы».
4. Студенты видят опубликованные материалы только своей группы. Загрузка, публикация и статистика им недоступны.
5. В статистике своего материала преподаватель видит всех зарегистрированных студентов группы, в том числе не открывавших материал: первое и последнее открытие, число открытий, число попыток и последний балл теста. Открытие не подтверждает прочтение. Все временные отметки хранятся в UTC, интерфейс показывает местное время браузера.

Сейчас одна учётная запись относится к одной группе; каждая команда создания преподавателя создаёт отдельную группу. Самостоятельной смены группы или роли нет. Код группы даёт доступ к её материалам — передавайте его только участникам группы.

Пароли хешируются scrypt с индивидуальной солью. Сессии живут 24 часа, хранятся на сервере по SHA-256 от случайного токена; браузер получает HttpOnly/SameSite=Strict cookie. Выход отзывает текущую сессию. Для изменяющих API-запросов обязателен заголовок `X-Study-Request: 1`; интерфейс добавляет его автоматически. Не включайте произвольный CORS. При размещении через HTTPS задайте `COOKIE_SECURE=1`.

## База данных

По умолчанию SQLAlchemy использует SQLite в `var/study.db` (исключена из Git). Таблицы создаются при старте. Данные переживают перезапуск; сохраните `var/` на постоянном диске и делайте резервные копии. Не включайте базу с реальными пользователями в общий снимок облачной среды.

Для PostgreSQL задайте `DATABASE_URL` в окружении сервера и административной команды, например `postgresql+psycopg://USER:PASSWORD@HOST:5432/study`. Пароль не сохраняйте в репозитории. База должна существовать заранее. PostgreSQL поддержан драйвером, но в текущей проверке использовалась SQLite; перенос существующих данных из SQLite автоматически не выполняется. Для последующих изменений схемы нужны миграции: `create_all` создаёт отсутствующие таблицы, но не обновляет существующие.

Проверки используют отдельную базу в памяти. Полный сценарий регистрации, публикации, запрета чужих материалов, учёта просмотров и серверной проверки теста работает с имитацией YandexGPT, не расходуя API-баланс.
