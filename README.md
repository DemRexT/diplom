# Суть — учебный помощник

Прототип бакалаврского диплома на Python 3.12 / FastAPI. Преподаватель загружает методичку и получает три блока: полный текст методички, её суть без воды и раздел, где студенты задают вопросы и получают ответы по тексту методички. Дополнительно генерируется тест с обратной связью. Интерфейс на HTML/CSS/JavaScript.

## Запуск

```bash
cd /workspace/diplom
python -m venv .venv
.venv/bin/pip install -r requirements.txt
export LLM_PROVIDER=gigachat
export GIGACHAT_CREDENTIALS='ваш ключ авторизации' # не сохраняйте в Git
export GIGACHAT_SCOPE=GIGACHAT_API_PERS
export GIGACHAT_MODEL=GigaChat
.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Для возврата к YandexGPT задайте `LLM_PROVIDER=yandex`, `YANDEX_API_KEY`, `YANDEX_FOLDER_ID` и при необходимости `YANDEX_MODEL=yandexgpt/latest`. Используется нативный Foundation Models API YandexGPT. Для сервисного аккаунта нужна роль `ai.languageModels.user` в каталоге Yandex Cloud, включённый биллинг и API-ключ с разрешением на вызов моделей. Ключ используется только сервером. Без ключа и ID каталога сайт открывается, обработка сообщает о недоступности. `.env.example` описывает переменные; автоматического чтения `.env` нет.

### Подключение GigaChat

Для переключения задайте процессу сервера:

```text
LLM_PROVIDER=gigachat
GIGACHAT_CREDENTIALS=ключ_авторизации_из_кабинета_GigaChat_API
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_MODEL=GigaChat
```

В PyCharm: Run → Edit Configurations → Environment variables. Записи разделяются точкой с запятой (или добавляются отдельными строками в редакторе). Используйте **ключ авторизации** API из кабинета GigaChat; не токен доступа от веб-чата и не Yandex API key. Не присылайте ключ в переписку и не сохраняйте в Git. Для личного аккаунта используется `GIGACHAT_API_PERS`; для бизнес-доступа задайте соответствующий scope из своего кабинета (`GIGACHAT_API_B2B` или `GIGACHAT_API_CORP`). Модель задаётся идентификатором, доступным вашему аккаунту; `GigaChat` — начальная настройка, стоимость и доступность проверяются у провайдера.

Сервер обменивает ключ на временный access token через `https://ngw.devices.sberbank.ru:9443/api/v2/oauth`, использует Bearer для `https://api.giga.chat/v1/chat/completions`, повторно использует токен внутри одной обработки и обновляет по сроку действия. При явном HTTP 401 токен обновляется и запрос повторяется ровно один раз. Тайм-ауты, ограничения частоты и прочие HTTP-ошибки автоматически не повторяются. JSON запрашивается промптом со схемой, не через неподдерживаемое предположение об OpenAI `response_format`.

Проверка TLS не отключается. Если появляется ошибка проверки сертификата, установите доверенные сертификаты согласно официальной инструкции GigaChat и при необходимости укажите PEM-файл в `GIGACHAT_CA_BUNDLE`. Приложение добавляет его к системным доверенным сертификатам; неверный файл приводит к понятной ошибке настройки. Альтернатива — стандартный `SSL_CERT_FILE` для HTTPX. Не используйте `verify=False`. Справка провайдера: [авторизация](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/post-token), [запрос к модели](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/post-chat).

После изменения переменных перезапустите сервер. `/health` показывает выбранного провайдера и наличие обязательных переменных, но не проверяет баланс и действительность ключа. Без `LLM_PROVIDER` остаётся YandexGPT для совместимости; для возврата задайте `LLM_PROVIDER=yandex`. Старые материалы не переписываются. Проверка JSON, вопросы по методичке и роли работают с обоими провайдерами. Новых Python-зависимостей не требуется. Платный запрос с реальным GigaChat-ключом не выполнялся: автоматические проверки используют имитацию OAuth и ответов API.

На Windows создайте окружение командой `py -3.12 -m venv .venv`, используйте `.venv\Scripts\python -m pip install -r requirements.txt` и `.venv\Scripts\python -m uvicorn app.main:app --reload`. Переменные в PowerShell задаются через `$env:LLM_PROVIDER="gigachat"`, `$env:GIGACHAT_CREDENTIALS="ваш ключ"`, `$env:GIGACHAT_SCOPE="GIGACHAT_API_PERS"`, `$env:GIGACHAT_MODEL="GigaChat"`.

Проверки: `.venv/bin/python -m pytest -q`. API-документация: `/docs`, состояние: `/health`.

## Ограничения прототипа

PDF с текстовым слоем или сканами, DOCX (абзацы и таблицы), TXT UTF-8; до 10 МБ и 200 страниц PDF; фиксированного ограничения в 45 000 символов больше нет. Страницы без достаточного текста распознаются локальным Tesseract OCR (до 50 страниц для OCR за загрузку). Сами файлы не сохраняются, но извлечённый из них текст хранится в базе вместе с сутью, тестом, вопросами студентов и ответами, пользователями, просмотрами и попытками тестирования. Текст передаётся внешнему провайдеру после отправки формы. Ответ нейросети проверяется по структуре, но достоверность требует сравнения с источником. Студент получает правильные ответы и объяснения только после отправки полного теста. Повторные попытки разрешены; это учебная самопроверка, не защищённый экзамен.

Перед публичным размещением необходимы HTTPS с `COOKIE_SECURE=1`, ограничение частоты/параллелизма запросов и затрат API, ограничение тела запроса на reverse proxy, изоляция парсеров документов и политика обработки данных. Сейчас это локальный прототип без этих мер.

## Развитие диплома

Перевод студентов между группами, восстановление паролей, ссылки на страницы источника, оценка качества сути и ответов на вопросы на наборе методичек, сравнение моделей. Основной исследовательский вопрос: насколько автоматически выделенная суть и ответы по тексту помогают усвоить материал без потери ключевых фактов.


## Пользователи, роли и учебные группы

Первого администратора создайте из папки проекта локальной командой (общего пароля по умолчанию нет):

```bash
.venv/bin/python -m app.manage admin --role admin --name "Администратор"
```

На Windows:

```powershell
.\.venv\Scripts\python.exe -m app.manage admin --role admin --name "Администратор"
```

Команда запрашивает пароль дважды без отображения символов (10–128 символов). Сервер и команда должны использовать одну базу данных. Создание администратора требует доступа к серверу, через публичную регистрацию получить эту роль нельзя.

1. Администратор входит с логином `admin`, создаёт группы и аккаунты преподавателей в кабинете, назначает преподавателей в группы или убирает назначения. У преподавателя нет возможности менять эти назначения, в том числе через прямые API-запросы.
2. Между преподавателями и группами связь «многие ко многим», программного ограничения на число назначений нет. Один преподаватель может иметь много групп, одну группу могут вести несколько преподавателей.
3. Преподаватель передаёт студентам код регистрации нужной группы. Студент регистрируется по этому коду и относится к одной группе. Код даёт доступ к материалам — передавайте его только участникам группы.
4. При загрузке преподаватель выбирает одну из назначенных ему групп. Материал сохраняется как черновик; после проверки содержания и вопросов преподаватель публикует его для выбранной группы.
5. В библиотеке и на странице материала студент видит имя преподавателя и группу. Преподаватели управляют только собственными материалами, даже если несколько преподавателей назначены в одну группу.
6. Если администратор убрал преподавателя из группы, доступ к загрузке и управлению его материалами в этой группе отзывается сразу. Уже опубликованные материалы остаются доступными студентам; повторное назначение возвращает преподавателю возможность управления. Удаление назначения не удаляет материалы или результаты.
7. Статистика собственного материала содержит всех зарегистрированных студентов выбранной группы: первое и последнее открытие, число открытий, попыток и последний балл с версией теста. Открытие не подтверждает прочтение. Время хранится в UTC, интерфейс показывает время браузера.

При необходимости преподавателя без групп можно создать локально: `.venv/bin/python -m app.manage teacher --name "Иван Иванов"`. После этого администратор назначает ему группы через кабинет. Старый параметр `--group` больше не используется.

### Редактирование теста

На странице своего материала преподаватель открывает вкладку «Проверить себя»: может изменить текст вопроса, четыре варианта, правильный вариант и объяснение, добавить или удалить вопросы. После нажатия «Сохранить тест» изменения сохраняются, версия теста увеличивается и материал снимается с публикации до повторной проверки. В черновике разрешено удалить все вопросы, но для публикации нужен хотя бы один. Максимум 50 вопросов на материал.

Результаты прежних попыток не удаляются и не пересчитываются по новым ответам. В статистике указан номер версии; ответы из давно открытой вкладки не принимаются, если тест уже изменился. Одновременные изменения теста в разных вкладках защищены проверкой версии.

Пароли хешируются scrypt с индивидуальной солью. Сессии живут 24 часа, хранятся на сервере по SHA-256 от случайного токена; браузер получает HttpOnly/SameSite=Strict cookie. Выход отзывает текущую сессию. Для изменяющих API-запросов обязателен заголовок `X-Study-Request: 1`; интерфейс добавляет его автоматически. Не включайте произвольный CORS. При размещении через HTTPS задайте `COOKIE_SECURE=1`.

## База данных

По умолчанию SQLAlchemy использует SQLite в `var/study.db` (исключена из Git). Схема создаётся и обновляется через Alembic при старте. Данные переживают перезапуск; сохраните `var/` на постоянном диске и делайте резервные копии. Не включайте базу с реальными пользователями в общий снимок облачной среды.

Для PostgreSQL задайте `DATABASE_URL` в окружении сервера и административной команды, например `postgresql+psycopg://USER:PASSWORD@HOST:5432/study`. Пароль не сохраняйте в репозитории. База должна существовать заранее. PostgreSQL поддержан драйвером, но в текущей проверке использовалась SQLite; перенос существующих данных из SQLite автоматически не выполняется. Миграции находятся в `migrations/`; последующие изменения схемы нужно оформлять отдельными ревизиями Alembic.

Проверки используют отдельную базу в памяти. Полный сценарий регистрации, публикации, запрета чужих материалов, учёта просмотров и серверной проверки теста работает с имитацией YandexGPT, не расходуя API-баланс.

## Ссылки на материалы

Каждый сохранённый материал открывается по отдельному адресу `/materials/ID`, например `/materials/12`. После обработки методички сайт автоматически переходит на страницу её черновика. Библиотека содержит обычные ссылки: их можно открывать в новой вкладке. На странице есть поле для копирования адреса и ссылка возврата в библиотеку. Перезагрузка и повторное открытие ссылки не вызывают нейросеть заново.

Если пользователь не вошёл, на странице ссылки показывается вход; после входа открывается тот же материал. Доступ остаётся ограниченным: преподаватель видит свои материалы, студент — опубликованные материалы своей группы. HTML-страница представляет только оболочку интерфейса, содержимое выдаётся защищённым API. Для доступа с другого компьютера в ссылке должен использоваться доступный адрес сервера, а не localhost.

## Обновление существующего проекта

Остановите сервер и из корня проекта выполните:

```powershell
git pull origin main
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Запустите сервер привычной конфигурацией Uvicorn. При первом обновлении старой SQLite-базы автоматически сохраняется копия `var/study.db.before-groups-migration.bak`, затем существующая связь преподавателя с группой переносится в таблицу назначений. Студенты, пароли, сессии, материалы и результаты сохраняются. Повторный запуск не восстанавливает назначения, удалённые администратором. Базу и резервную копию не добавляйте в Git. Для PostgreSQL перед обновлением сделайте резервную копию средствами PostgreSQL.

После обновления создайте администратора командой выше. Существующие преподаватели продолжают пользоваться прежними аккаунтами.

## PDF-сканы и OCR

Для PDF, из которого нельзя скопировать текст, добавлено локальное распознавание. Страницы с текстовым слоем читаются напрямую; страницы с менее чем 40 символами текста и содержимым дополнительно распознаются. Поддерживаются смешанные документы. Распознанный текст передаётся в YandexGPT обычным способом. Качество зависит от чёткости, ориентации и вёрстки скана; таблицы и формулы могут распознаваться неточно.

На Windows:

1. Установите Tesseract OCR по инструкции из [официальной документации](https://tesseract-ocr.github.io/tessdoc/Installation.html) (раздел Windows; там указаны сборки для Windows). Программа ищет `tesseract` в PATH и в `C:\Program Files\Tesseract-OCR\tesseract.exe`.
2. В терминале PyCharm из корня проекта выполните:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m app.setup_ocr
```

Вторая команда скачивает официальные языковые модели rus/eng из фиксированной ревизии `tesseract-ocr/tessdata_fast` в игнорируемый каталог `var/tessdata` и проверяет SHA-256. Она не устанавливает сам движок Tesseract и не заменяет уже существующие отличающиеся модели. Библиотека PDFium для преобразования страниц в изображения устанавливается через pip; Poppler и Ghostscript не нужны.

3. Если Tesseract установлен в другой каталог, добавьте в Environment variables конфигурации Uvicorn:

```text
TESSERACT_CMD=C:\путь\к\Tesseract-OCR\tesseract.exe
```

4. Полностью перезапустите сервер и загрузите PDF ещё раз.

На Ubuntu/Debian движок ставится командой `sudo apt-get install tesseract-ocr`; затем также выполните `python -m app.setup_ocr` из виртуального окружения. В текущей облачной среде движок уже установлен.

Дополнительные переменные: `OCR_LANG` (по умолчанию `rus+eng`), `OCR_TESSDATA_DIR` (необязательный путь к языковым моделям). Без переопределения программа выбирает `var/tessdata`, если он существует, иначе использует языки установленного Tesseract.

Лимиты: до 50 распознаваемых страниц в одном PDF, до 300 секунд суммарно на OCR и 30 секунд на одну страницу. Сохраняются общий размер файла 10 МБ и максимум 200 страниц PDF. Длинный извлечённый текст автоматически обрабатывается по частям, без отказа на 45 000 символов. Рендеринг ограничен 12 млн пикселей и 10 000 пикселей по одной стороне. Временные изображения удаляются после обработки, OCR работает в потоке вне основного цикла сервера. Перед публичным размещением всё равно нужна изоляция парсеров и ограничение параллельных загрузок.

## Материал: методичка, суть, вопросы

После загрузки преподаватель (а после публикации — студенты группы) видит материал в четырёх вкладках:

1. **Методичка** — весь текст, извлечённый из файла, без обработки нейросетью и без форматирования. Для сканов это результат OCR. Разметка внутри текста отображается как текст и не выполняется.
2. **Суть** — главное содержание методички без воды: ключевые понятия и определения, правила, формулы с расшифровкой, алгоритмы по шагам, условия и выводы. Вводные фразы, повторы, отступления и однотипные примеры убираются. Ориентир в промпте — 10–25% содержательного объёма, без потери основных тем.
3. **Вопрос по методичке** — студент пишет вопрос и получает ответ, построенный только по тексту методички. Если ответа в тексте нет, помощник так и отвечает. Каждый вопрос и ответ сохраняются: студент видит свою историю, преподаватель — вопросы всех студентов по своему материалу и может задать вопрос сам, чтобы проверить ответы перед публикацией.
4. **Проверить себя** — тест из пяти вопросов, как раньше: преподаватель редактирует его, студент проходит, результаты попадают в статистику.

Карточки, интерактивные эксперименты и мини-игры убраны. Материалы, загруженные до обновления, открываются: суть и тест на месте, но полного текста методички у них нет (исходный текст тогда не сохранялся). Чтобы появились вкладка «Методичка» и точные ответы на вопросы, загрузите методичку заново. На вопросы по старым материалам нейросеть отвечает только по сути.

## Обработка больших методичек

Документ до 30 000 символов отправляется для выделения сути одним запросом. Более длинный текст сначала делится на фрагменты не более 18 000 символов (по границам абзацев или слов), по каждому модель пишет опорные заметки; при необходимости заметки объединяются и сокращаются повторно. Суть и тест строятся по этим заметкам. Все фрагменты участвуют в обработке, конец документа не обрезается. Порог 45 000 символов удалён.

Модель может упустить детали или ошибиться, особенно после OCR; сверяйте суть с вкладкой «Методичка» перед публикацией.

При ошибке подготовки сути или теста материал не сохраняется. Повторная загрузка начинает обработку заново и может повторно тарифицироваться. При сетевых ошибках, ошибках HTTP или ограничениях провайдера автоматических повторов нет; для невалидного итогового JSON разрешён один отдельный запрос исправления структуры.

Загрузка из браузера использует `POST /api/material?stream=true` (поток NDJSON): пока идёт обработка, приходят служебные `heartbeat`, затем `complete` с сохранённым черновиком или `error`. Обычный `POST /api/material` возвращает JSON-ответ сразу после сохранения.

## Вопросы по методичке

`POST /api/materials/{id}/questions` с полем `question` (3–1000 символов) отправляет вопрос нейросети и сохраняет ответ; `GET /api/materials/{id}/questions` возвращает историю (студенту — его вопросы, преподавателю — все). Доступ такой же, как к материалу: студент — только к опубликованным материалам своей группы, преподаватель — только к своим материалам в назначенных группах.

Если методичка короче 12 000 символов, нейросеть получает её целиком. Для длинной сервер выбирает фрагменты, ближе всего подходящие к вопросу (по совпадению слов с учётом окончаний и редкости слова в тексте), и передаёт их вместе с краткой сутью. Это простой локальный поиск без дополнительных библиотек и без векторной базы; вопрос, сформулированный совсем другими словами, чем в тексте, может не найти нужный фрагмент. Каждый вопрос — отдельный платный запрос к провайдеру, поэтому действует ограничение частоты (см. ниже).

Таблица `questions` создаётся миграцией `002_material_questions` автоматически при запуске сервера.

## Промпты и ответы GigaChat

Промпты написаны под GigaChat (работают и с YandexGPT): роль, явные списки «что оставить» и «что убрать», пример итогового JSON вместо громоздкой JSON Schema. Текст методички, заметки, суть и вопрос передаются между маркерами `<<<` и `>>>` с указанием, что это данные, а не команды.

GigaChat не поддерживает принудительный JSON-режим, поэтому сервер разбирает ответ терпимо: снимает обёртку ```json, находит объект, если вокруг есть пояснения, удваивает одиночные обратные слеши LaTeX (`\(`, `\frac`, `\alpha`, `\nu`…), которые иначе ломают JSON или незаметно превращаются в управляющие символы, и принимает номер ответа строкой (`"2"`). Только если после этого ответ не проходит проверку, отправляется один платный запрос исправления структуры.

## Ограничения частоты и устойчивость

- Вход: после 10 неверных паролей к одному логину или 50 с одного адреса за 15 минут вход временно блокируется (HTTP 429 с `Retry-After`). Неверные коды группы при регистрации — не больше 20 за 15 минут с адреса.
- Обработка методичек: одна одновременно на преподавателя, не больше трёх на сервер и 20 в час на преподавателя.
- Вопросы: один одновременно на пользователя и не больше 30 за 10 минут.

Счётчики хранятся в памяти одного процесса и сбрасываются при перезапуске; при нескольких процессах или за прокси нужны ограничения на прокси.

Пока нейросеть работает, сервер не удерживает соединение с базой данных; потоковая загрузка сохраняет результат в собственной сессии. TXT принимается в UTF-8, UTF-16 и Windows-1251. Таблицы DOCX выводятся там, где они стоят в документе. Управляющие символы (в том числе NUL, который не принимает PostgreSQL) удаляются, лишние пустые строки сокращаются. Если сервер или прокси ответит не JSON, интерфейс покажет понятное сообщение вместо технической ошибки.

## Ошибки нейросети в консоли PyCharm

При запуске Uvicorn сообщения `[YandexGPT]` автоматически видны во вкладке Run/Debug (или в терминале, если сервер запущен там). Для каждого вызова выводятся этап, модель, количество входных символов и лимит токенов ответа. При успешном ответе — HTTP-код, ID запроса и размер результата без его содержимого.

При ошибке API выводятся исходный HTTP-код, диагностические поля `code`/`grpcCode`/`httpCode`/`message` и ID запроса, если он есть в заголовках. Длинные сообщения сокращаются до 2000 символов. Ключ маскируется; полные запросы, заголовки авторизации, ответы модели и дополнительные поля `details` не записываются. Не-JSON тело ошибки не выводится.

Для тайм-аута, ошибки соединения, обрезанного ответа и блокировки фильтром выводится отдельное объяснение. Если нейросеть вернула невалидный JSON, в консоли будут строка и столбец ошибки; если JSON не соответствует схеме — поле и причина, например `quiz → 0 → options: too_short`. Входные значения полей при проверке схемы в лог не включаются. На сайте остаются понятные сообщения без технических подробностей. Дополнительные настройки логирования не нужны; если меняли уровень Uvicorn, `--log-level info` включает и прогресс, ошибки видны и при `--log-level error`.

## Автоматическое исправление структуры результата

Первый итоговый запрос содержит JSON Schema с обязательными полями и ограничениями. Если ответ не является валидным JSON либо не проходит проверку структуры (например, нет `title`, `summary`, `quiz`, неверное число вариантов или индекс ответа), сервер отправляет **ровно один** дополнительный запрос. В нём передаются исходный подготовленный материал, список ошибок без значений полей и, если они достаточно компактны, предыдущие поля названия и теста. Ответ снова проходит ту же проверку схемы.

Если в первом ответе уже есть непустой строковый `summary`, он сохраняется при исправлении остальных полей и не генерируется заново. Корректный ответ без ошибок дополнительных запросов не вызывает. Исправление тарифицируется как обычный запрос YandexGPT.

В консоли видны сообщения `Исправление структуры: попытка 1/1`, затем успех или отказ после второй проверки. Если исправление не удалось либо провайдер вернул ошибку, частичный материал не записывается в базу. Это сохранение в памяти одного запроса, а не долговременный кэш: после завершившейся ошибкой загрузки или перезапуска сервера повторная загрузка снова начнёт весь процесс. Сетевые ошибки, тайм-ауты, фильтр содержимого и обрезанные ответы не вызывают автоматических повторов.

## Формулы, схемы и оформление сути

Суть и ответы отображают математические формулы через KaTeX. Поддерживаются старые разделители `$...$`, `$$...$$` и новые `\(...\)`, `\[...\]`; индексы, дроби, множества и другие поддерживаемые конструкции LaTeX выводятся математическим набором. Это работает также в ответах на вопросы, вопросах теста и объяснениях ответов. В редакторе преподавателя исходная разметка остаётся в полях ввода, чтобы её можно было менять. Невалидная формула не ломает остальную страницу; корректность распознанных символов после OCR по-прежнему нужно проверять.

Промпт предлагает модели добавлять небольшие Mermaid-схемы там, где источник содержит подходящие связи, классификации или процессы. Они сохраняются в тексте сути в блоках `mermaid` и отображаются рядом с объяснением. Поддерживаются flowchart/graph, mindmap, sequenceDiagram и pie (числа должны браться из источника). Схемы дополняют текст сути; их наличие зависит от содержания и ответа модели. Дополнительно отображаются тематические заголовки, жирные понятия, списки и выделенные блоки `> Важно:` / `> Пример:`.

Библиотеки и математические шрифты находятся в `app/static/vendor`: дополнительная установка на ПК, Node.js и CDN не нужны. Версии, происхождение и лицензии приведены в README этого каталога. Для нового оформления и схем обновите проект и перезагрузите браузер через Ctrl+F5. Уже сохранённые корректные формулы будут отображаться сразу; новые схемы автоматически не добавляются в старые материалы — для этого повторно загрузите исходную методичку.

Содержимое нейросети не вставляется как произвольный HTML. KaTeX работает с `trust: false`, Mermaid — с `securityLevel: strict` и отключёнными HTML-подписями; результирующий SVG дополнительно очищается DOMPurify. В схемах запрещены пользовательские настройки, HTML, ссылки, изображения и обработчики событий. Размер описания схемы ограничен 12 000 символов и 80 связями. Некорректная схема заменяется сообщением, остальная часть текста доступна. Схемы и формулы обрабатываются локально в браузере, дополнительный вызов нейросети для их отображения не требуется.

Суть поддерживает Markdown: заголовки `#`–`######`, жирный текст `**...**`, курсив, вложенные списки, цитаты и таблицы. Таблицы выводятся с заголовками, границами и горизонтальной прокруткой на узких экранах. Формулы обрабатываются отдельно от Markdown, поэтому индексы, обратные слеши и символ `|` внутри формулы не повреждают разметку. Для явно оформленных строк таблицы с внешними `|` допускается пропущенная строка разделителя заголовка. Оформление применяется при просмотре, без изменения содержимого сохранённых материалов. После обновления перезапустите сервер и нажмите Ctrl+F5; повторная генерация для исправления отображения не требуется.

Она открывает страницу с фиктивными данными без сервера и обращений к нейросети, проверяет формулы, обработку неверной формулы, таблицы, вывод полного текста без выполнения разметки, отправку вопроса и мобильную ширину.
